# Independent hosting: GitHub → Vercel + Render + Supabase

The frontend keeps the current design and pages. The cloud backend uses PostgreSQL and private object storage instead of local files. Speech uses Groq (explicitly authorized by the owner); the Mac version still uses the installed MLX model unless configured otherwise. This is feature parity, not identical model inference.

## 1. Create the accounts

Sign up with GitHub at https://supabase.com/dashboard, https://dashboard.render.com, and https://vercel.com/signup. Authorize access to the private `gaade-kosha` repository. Keep database passwords, service-role keys and provider keys in service environment settings, never in GitHub or frontend variables.

## 2. Supabase

Create a Free project and save its database password privately. In **Connect**, choose the **Session pooler** connection string (IPv4-compatible). Use it as `DATABASE_URL` on Render. The backend uses psycopg, TLS, a small connection pool, and its own `gaade` schema; do not expose that schema in Supabase Data API settings. PostgreSQL is authoritative, including contribution approval states and translation drafts.

Also collect the project URL (`SUPABASE_URL`) and the backend-only service-role JWT (`SUPABASE_SERVICE_ROLE_KEY`) from Supabase API settings. Storage remains private: startup creates/verifies the `gaade-private` bucket. Do not mark that bucket public. Only token-authenticated moderation can retrieve contribution recordings; narration is served by the backend for approved records.

## 3. Render backend

Choose **New → Blueprint**, connect this GitHub repository, and use the root `render.yaml`. The blueprint specifies a Free Docker web service, installs FFmpeg, and uses `project/Dockerfile`. Supply the variables marked `sync: false`:

- `DATABASE_URL`: Supabase Session pooler PostgreSQL URI, with password properly URI-encoded.
- `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`.
- `GROQ_API_KEY`, `GEMINI_API_KEY`: the existing provider keys from the local ignored `.env`.
- `FRONTEND_ORIGIN`: the exact production Vercel origin, without a trailing slash. Set this after Vercel assigns its URL if necessary.

`ADMIN_TOKEN` is generated by Render. Copy it privately from Render settings to use the Review page; the local admin token remains local. No API keys are embedded in the frontend build.

The initial boot copies approved seed records and translation drafts only when the database is empty. Subsequent starts preserve live records. `project/data` is ignored and never shipped. PostgreSQL, private recordings, and cached narration survive Render restarts because they are stored in Supabase. The temporary Render filesystem is only a cache.

After deployment, verify `https://YOUR-API.onrender.com/api/health`. Note the actual Render origin for Vercel. No service is published merely by pushing source to GitHub; account configuration is required.

## 4. Vercel frontend

Import the same repository. Set **Root Directory** to `project/frontend`, use the Vite preset, build `npm run build`, and output `dist`. Set the public environment variable:

```
VITE_BACKEND_ORIGIN=https://YOUR-API.onrender.com
```

Use only the origin, without `/api` or a trailing slash. Deploy, then set Render's `FRONTEND_ORIGIN` to the exact resulting `https://YOUR-SITE.vercel.app` origin and redeploy/restart the backend. This is a static frontend with direct HTTPS API requests, so audio does not pass through Vercel Function payload limits.

## Existing private data migration (optional, direct to cloud)

The checked-in seed contains only approved public records and their existing translation drafts. To copy pending/rejected records, private recordings, and cached narration as well, configure an ignored `project/.env.cloud` file locally with the database/storage settings, then run:

```
project/.venv/bin/pip install -r project/backend/requirements-cloud.txt
project/.venv/bin/python project/scripts/migrate_cloud.py
project/.venv/bin/python project/scripts/migrate_cloud.py --apply
```

Inspection is the default. `--apply` copies all statuses and original IDs; source SQLite is read-only. Existing differing remote rows or drafts stop migration instead of overwriting remote edits. Private audio goes directly to private storage, never through GitHub. Partial failed uploads may leave unreferenced private objects; rerunning with matching rows is safe. Keep a local backup until the hosted records/audio have been verified.

## Verification before calling it complete

- Home search: English and Kannada typed situations; Gemini and Groq selection; keyword fallback.
- Dictionary: all records, filters, details, bilingual drafts and provenance.
- Voice: HTTPS microphone permissions on desktop/mobile, browser English dictation, server Kannada/English transcription, contribution upload and transcription.
- Narration: play/pause/stop, repeat audio after restarting Render, and a record with Kannada explanation.
- Contributions/review: submitted item remains private, unauthorized moderation/audio returns 401, authorized review updates public search.
- Durability: restart Render and confirm records, translations, recordings, and narration persist.

GitHub Actions runs synthetic SQLite/PostgreSQL and mocked-provider tests plus browser journeys. Real cloud account connectivity and physical microphone quality must still be checked on the deployed URLs.

## Free-tier limits and differences

Render Free can sleep after inactivity; expect a cold start on the first request. Supabase Free storage/database quotas and provider speech/search/narration quotas still apply. This setup does not promise unlimited traffic, uptime, or zero cost beyond free quotas. Keep paid billing disabled if spending must remain zero.

The 470 MB local E5 semantic model is not loaded on the free Render service. Hosted search defaults to the configured Gemini/Groq catalog matching, while the ordinary search option remains database keyword search. Optional local E5 and Apple MLX speech still work in the Mac development configuration. Free cloud inference cannot be presented as numerically identical to the Mac's models.
